# Skill 层改进计划

> 生成日期：2026-08-02
>
> 范围：根 `SKILL.md` 与 `skills/*/SKILL.md`，不涉及 bridge、Chrome 扩展和业务实现。

## 结论

当前 skill 已覆盖认证、内容发现、互动、发布和复合运营，能力边界也有明确的 CLI 白名单。主要风险不在能力不足，而在触发竞争、规则重复和文档漂移：不同 Agent 平台可能重复触发根 skill 与子 skill，部分流程存在互相矛盾的约束，命令清单也有不同步现象。

## P0：优先修复

### 1. 明确根 skill 与子 skill 的触发关系

- 根 skill 改为只处理跨能力复合任务和路由，不要用“任何小红书操作都触发”的宽泛描述。
- 子 skill 保持独立、互斥的触发范围。
- 明确 `xhs-content-ops` 与 `xhs-explore`、`xhs-interact`、`xhs-publish` 的边界。
- 增加“只选择一个主 skill；复合任务按阶段调用其他 skill”的规则。

### 2. 将“内容工作”和“账号操作”分流

- 纯文案生成、标题优化、内容分析不要求 bridge、Session ID 或登录状态。
- 搜索、读取账号数据、互动、发布等真实账号操作才执行 bridge 前置检查。
- 避免每次触发都运行 `check-login`，减少无关二维码、网络和凭证依赖。

### 3. 统一用户输入工具抽象

统一写成“使用当前 Agent 运行时提供的用户输入工具；没有工具时输出编号问题并暂停”，不要在子 skill 中硬编码 `AskUserQuestion`。

### 4. 建立单一 CLI 命令来源

修正各 skill 的命令白名单与 CLI 实际命令不一致的问题：

- `xhs-publish` 的白名单补充 `save-draft`；
- 子 skill 的前置检查命令处理方式统一；
- `xhs-auth` 是否暴露 `phone-login` 要做明确选择；
- 后续用脚本自动检查白名单与 `scripts/cli.py` 的 parser 是否同步。

## P1：结构和安全改进

### 5. 减少重复规则

根 skill 保留共享规则：命令边界、凭证处理、确认策略、失败处理和路由原则。子 skill 只保留自身的触发条件、输入要求、流程和输出格式，避免重复维护 bridge 规则。

### 6. 重做副作用确认策略

- 发布、退出登录必须确认。
- 单次点赞、收藏、评论可视为用户明确指令，但批量操作必须先展示目标数量和列表。
- 批量互动增加默认上限，超过上限再次确认。
- 用户取消发布时询问“保存草稿”还是“放弃”，不要强制保存草稿。

### 7. 降低运营建议的确定性

将“每天不超过 20 条”“间隔 30～60 秒”等内容标记为保守建议，不表达为安全阈值。遇到限流、验证码或异常页面时应立即停止并报告。

### 8. 凭证与临时文件规则

- bridge token、Session ID 不回显到日志或最终回复。
- `.env` 应加入 git 忽略，并在文档中说明权限保护和轮换方式。
- 临时标题/正文文件使用唯一文件名，任务完成后清理或明确保留位置。

## P2：兼容性与验证

### 9. 修正 skill metadata

当前顶层 `version` 字段不符合 `skill-creator` 的 `quick_validate.py` 允许字段。需要根据目标平台选择：

- 兼容 Codex：移除顶层 `version`，并按需补充 `agents/openai.yaml`；
- 仅服务 OpenClaw：保留 OpenClaw 元数据，但不要再宣称所有 SKILL.md 平台都完全兼容。

### 10. 增加 skill 回归用例

至少覆盖以下请求：

- “搜索笔记并总结”；
- “帮我写文案但不要发布”；
- “直接发布这组图片”；
- “取消发布”；
- “批量点赞 30 条”；
- “分析竞品但不登录小红书”；
- “检查登录并扫码”。

验证触发的主 skill、是否需要 bridge、是否需要确认、最终允许的 CLI 命令和停止条件。

## 推荐实施顺序

1. 修正 metadata 和命令白名单；
2. 收窄根 skill 触发描述，建立明确路由表；
3. 分离内容生成与真实账号操作；
4. 统一确认与批量操作规则；
5. 删除重复通用文本；
6. 增加命令同步检查和 prompt 回归用例。
