# 用户交互规范

在收集信息、请求确认或让用户选择下一步前读取本文件。

## 用户交互工具

当 skill 需要向用户提问、收集信息或请求确认时，按以下优先级使用当前运行时实际提供的第一个工具：

1. `AskUserQuestion`
2. `request_user_input`
3. `clarify`
4. `ask_user`

- **批量提问**：工具支持单轮多问时，将同一阶段的相关问题合并为一次调用；只支持单问时，按信息依赖顺序逐个提问，不把同一阶段拆成多条独立消息。
- **阻塞原则**：用户未回答前，不继续执行后续步骤；不替用户做假设，也不从历史上下文推断当前意图。
- **回退方案**：四种工具均不可用时，输出带编号的纯文本问题，要求用户回复编号或答案，然后暂停。

## 必须询问的场景

| 场景 | 是否必须询问 | 可跳过的情况 |
|---|---|---|
| 首次配置 bridge 三件套 | 是 | 用户级配置已存在且验证通过 |
| 登录方式选择（二维码/手机） | 是 | `check-login` 返回唯一可用方式 |
| 发布图文/视频/长文 | 是，执行前确认 | 用户当前消息明确要求“直接发布 / 不用确认 / 跳过确认” |
| 退出登录 | 是，执行前确认 | 用户当前消息明确要求“直接退出 / 不用确认” |
| 点赞/收藏/评论/回复 | 否 | — |
| 搜索/浏览/获取详情 | 否 | — |
| 需要用户输入手机号 | 是，每次都问 | 无 |
| 需要用户输入验证码 | 是 | 无 |
| 批量互动 | 是 | — |
| CLI 必填信息缺失 | 是 | — |

批量互动确认前必须展示目标数量和列表；超过保守默认上限时再次确认。只读的搜索、详情读取、竞品分析和热点追踪连续步骤不逐步等待确认。

## 禁止行为

- 不从历史对话、记忆或上下文推断手机号、验证码或 Session ID；
- 未确认时不执行发布或退出登录；
- 不把同一阶段的多个问题拆成多轮消息轰炸用户；
- 用户取消填写后的发布时，询问“保存草稿”或“放弃”；只在选择保存时执行 `save-draft`。
